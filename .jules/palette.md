## 2024-06-10 - Missing Accessibility Primitives on Custom Interactive Elements
**Learning:** In this app, custom interactive components (like the `sheet-header` used as an accordion toggle) are built using non-interactive elements (e.g., `<div>`) with only `onClick` handlers. This results in a pattern where essential accessibility primitives—such as `role="button"`, `tabIndex={0}`, `aria-expanded`, and keyboard event handlers (`onKeyDown`)—are missing, breaking keyboard navigation and screen reader support.
**Action:** Always ensure that custom interactive components built with non-interactive HTML tags are explicitly granted the correct ARIA roles, are included in the tab order via `tabIndex`, use appropriate ARIA state attributes (like `aria-expanded` or `aria-selected`), and implement full keyboard support (handling 'Enter' and 'Space' keys). Alternatively, prefer using native semantic HTML elements like `<button>` or `<details>`/`<summary>` which provide these features out-of-the-box.
