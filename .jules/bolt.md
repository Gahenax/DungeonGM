## 2024-06-25 - Missing Indexes on Temporal Queries in SQLite
**Learning:** Found a performance bottleneck where querying `get_campaign()` or `get_character()` without providing an ID defaulted to `SELECT * FROM campaigns ORDER BY created_at DESC LIMIT 1`. Without an index on `created_at`, SQLite performs a full table scan, resulting in O(N) performance that linearly degrades as the number of entities grows.
**Action:** Added `CREATE INDEX IF NOT EXISTS` for the `created_at` column in both the `campaigns` and `characters` tables within `database.py`'s initialization logic. Always verify that tables queried with `ORDER BY ... LIMIT` have appropriate covering or sorted indexes to ensure O(log N) performance, especially in local SQLite databases that can accumulate thousands of records.
